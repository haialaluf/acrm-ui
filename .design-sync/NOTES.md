# design-sync notes — acrm-ui

Repo-specific gotchas for future syncs. Read this before re-running.

## Shape: this is an app, not a component library

- `acrm-ui` is a private Vite app with **no library build, no `dist/` entry,
  no shipped `.d.ts`, and no Storybook**. The converter's own last-resort
  synth-entry (`export * from` every `src/**/*.tsx`) is useless here: the
  components are **default exports**, which `export *` does not re-export, and
  it would drag in routes, queries and contexts.
- So the sync uses a hand-maintained barrel, **`.design-sync/entry.tsx`**,
  passed as `--entry`. One named export per component. `componentSrcMap` in
  the config lists exactly the same names (that is what makes the component
  list; there are no `.d.ts` exports to discover).
- **Adding a component to the sync = add it to BOTH** `.design-sync/entry.tsx`
  and `cfg.componentSrcMap`. The generator that built the map from the barrel
  is in git history only; keeping the two in step by hand is fine at this size.

## Scope rule: prop-driven only

Only components that render from props alone are synced. Anything importing
`@/queries/*`, `@tanstack/react-router`, `@/stores/*`, `@/contexts/*`, or a
data hook (`useAuth`, `useMedia`, `useThread`, …) at **runtime** is excluded —
it renders blank or throws in a static preview. Type-only imports of those
modules are fine (they erase).

Deliberately excluded even though they are prop-driven:

- `StatusIcon` — renders `<use href="/icons.svg#…">`; the sprite is a public
  asset the artifact does not serve, so it always paints nothing.
- `VideoThumb` — needs a real video URL to produce a frame.
- `automations/flow/*` (`FlowCanvas`, `FlowEdge`, `nodes`) — need `@xyflow`
  React Flow context.

## Supabase client stub (required — the build fails without it)

`src/supabase/client.ts` calls `createClient(import.meta.env.VITE_SUPABASE_URL!, …)`
**at module scope**. In the esbuild IIFE bundle `import.meta` is `{}`, so
importing it anywhere throws before React mounts. `.design-sync/tsconfig.sync.json`
aliases `@/supabase/client` → `.design-sync/stubs/supabase-client.ts`, which
re-exports the same type modules and exports an inert `supabase`.

**If `client.ts` gains new `export * from "./types/…"` lines, regenerate the
stub** — it mirrors that list, and a missing re-export fails the bundle with
`No matching export in ".design-sync/stubs/supabase-client.ts" for import "X"`.

## Stylesheet: copied from the app build, not committed

Tailwind v4 utilities only exist after a Vite build, so `cfg.cssEntry` points
at `.design-sync/styles.compiled.css` — **a copy of `dist/assets/index-*.css`**
(gitignored; the dist filename is content-hashed, so it cannot be referenced
directly). Before each sync:

```sh
npm run build && cp dist/assets/index-*.css .design-sync/styles.compiled.css
```

Skip that and the sync ships whatever CSS the last build produced — stale
utilities, missing new classes.

## Known render warns (expected — not new findings)

- `[RENDER_THIN] Spinner`, `[RENDER_THIN] CopyButton` — both are genuinely
  tiny icon-only components with no text. Correct as-is.
- `[FONT_MISSING] "Inter", "Lucida Grande"` — **the app ships no webfonts by
  design**: `html, body` use a pure system stack (Segoe UI / Helvetica Neue /
  … / Lucida Grande). "Inter" comes from the vendored `@maily-to/core`
  editor CSS. Nothing to source; do not add a substitute font.
- `[TOKENS_MISSING]` for `--scrollbar-*` and `--button-var-border-color` —
  set at runtime / by vendored CSS, not by a shipped stylesheet.
- `[DOCS_UNMAPPED]` for every component — the repo has no per-component docs;
  `.prompt.md` is synthesized from props + JSDoc, which is accurate here since
  most components carry a real leading JSDoc comment.

## Card layout overrides

`Button`, `SectionItem`, `WizardHeader` are `cardMode: "column"` — their
stories are wider than a grid cell and got cropped otherwise (`[GRID_OVERFLOW]`).

## Re-sync risks

- **Stale CSS** is the top risk: `styles.compiled.css` is gitignored and
  regenerated by hand (see above). A fresh clone has no copy at all and the
  build fails on a missing `cssEntry`.
- **Barrel drift**: components added to `src/components/` never appear in the
  sync until someone edits `.design-sync/entry.tsx`. Nothing warns about this.
- **Scope drift the other way**: a synced component that later grows a
  `useQuery`/router import starts rendering blank. `[RENDER]`/`[RENDER_BLANK]`
  catches it — the fix is to drop it from the barrel and the config, not to
  add a provider.
- The `.d.ts` contracts come from source inference (no shipped types), so a
  component whose props are a complex generic may emit a weak `<Name>Props`.
  `cfg.dtsPropsFor` is the escape hatch; none was needed on the first sync.
- Authored previews live in `.design-sync/previews/` (15 of them, all graded
  good). The other 77 components ship the deliberate floor card — authoring
  more is a valid incremental job for any later re-sync.
- Playwright: the render check used `playwright@1.62.1`, matching the
  `chromium-1234` build already in `~/Library/Caches/ms-playwright`. A
  different playwright version will fail with "Executable doesn't exist".
